==================================================
P0-01 — STANDARDIZE API Result<T> HANDLING
==================================================

Inspect:

packages/shared_core/lib/src/network/api_client.dart

Current architecture returns:

Future<Result<T>>

where failures are returned as:

Failure(...)

rather than always thrown.

Many Flutter datasources currently do things like:

await _client.post(...);

and discard the returned Result.

This creates false-success behavior.

Choose ONE architecture and enforce it project-wide.

Preferred options:

OPTION A:

Datasource returns Result<T>
and provider/repository handles:

switch (result) {
  case Success():
  case Failure():
}

OR:

OPTION B:

Datasource unwraps Result and throws typed exceptions:

final result = await _client.post(...);

return result.when(
  success: (data) => data,
  failure: (error) => throw error,
);

Then upper layers use try/catch consistently.

DO NOT mix the two patterns randomly.

Create reusable helper if useful:

extension ResultUnwrap<T> on Result<T> {
  T unwrapOrThrow() ...
}

or equivalent.
