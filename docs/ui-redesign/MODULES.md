## Recommended migration order + reasoning

`phase-0 (M0) → phase-1 (M1) → phase-2 (M2 auth, unblocks all logins) → phase-3 (M3 advisor core, highest revenue/traffic) → phase-4 (M4 inspection, fragile, needs M3) → phase-5 (M5 supervisor/tech/common, same app shell) → phase-6 (M6 customer, highest external visibility, dark-mode reference) → phase-7 (M7 owner, depends on staff/customer data shapes conceptually) → phase-8 (M8 CRM, internal/low traffic, most tolerant of delay) → ux-writing → l10n ×3 → goldens ×2 → polish`.

Large modules split: advisor → core (phase-3) + inspection/repair (phase-4); supervisor+technician+common merged (phase-5) since they share `staff_app` shell and are each small alone; owner dashboard+job_cards merged (phase-7); customer kept whole (phase-6) but run in 2+ sessions internally if needed; CRM whole (phase-8).
