## The two answers

- **Would a first-time user know what to do in 3 seconds?** Yes on every screen: `Welcome back` + `Log in to continue.` with two labelled fields and one `Continue`; `Supervisor access` with username + password and one `Sign in`; `Confirm your number` + `Enter the 6-digit code we sent you.` with six boxes and `Resend in 30 seconds`; `What's your name?`, `How should we contact you?`, `Create your password`, `Forgot your password?`, `Choose a new password`, `Password updated` each ask exactly one thing with exactly one button. The 3-second read never requires scrolling, searching, or choosing between tabs.
- **What would an Airbnb product designer reject here?** Nothing structural — the one-screen password/supervisor, headline-first hierarchy, sticky CTA, alt-row pattern (switcher correctly killed), resend link, masked-destination banner and terminal `Password updated` screen are exactly the C16 playbook applied under the scoped rule (frequent tasks single-screen). None of these is a tap-count, one-path, or background violation; none blocks blessing.
